# Pacman Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a polished, responsive Pacman game to the vibe-fun MCP game catalog.

**Architecture:** Package the game as one self-contained HTML document like the existing catalog entries. Keep the deterministic maze and game rules in the embedded script, render the action through one DPR-aware canvas, and use a small optimized generated raster texture only as an optional decorative layer so gameplay remains fast and offline-safe.

**Tech Stack:** TypeScript, self-contained HTML/CSS/ES5-style JavaScript, Canvas 2D, Node test runner, MCP Apps bridge.

## Global Constraints

- The game must work with keyboard, swipe, and on-screen directional controls.
- The app must contain no external URLs or runtime-loaded assets.
- Game state must save through `mcpApp.save` and restore through `mcpApp.load`.
- Rendering must use `requestAnimationFrame`, device-pixel-ratio scaling, and no per-frame DOM creation.
- Generated imagery must be compressed and embedded within the app's HTML byte budget.
